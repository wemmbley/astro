# Модули

Модуль - это специфическая доменная область, с конкретной архитектурой.

# Слои

Business - изменяемая телеологическая реализация словаря, онтологии на практике с целевым намерением.
Esoteric - неизменяемое онтологчиеское ядро предметной области, что вообще есть и каково оно.
Technical - это уже технически-инфраструктурный слой, не относится к бизнесу и к онтологчиескому словарю.
Common - shared-слой, сюда складываем только то, что необходимо шарить везде.

```
┌─────────────────────────────────────────┐
│               TECHNICAL                 │  (Внешний слой: контроллеры, API-клиенты, логгеры)
│   ┌─────────────────────────────────┐   │
│   │            BUSINESS             │   │  (Сценарии: расчет натала, проверка Stripe)
│   │   ┌─────────────────────────┐   │   │
│   │   │        ESOTERIC         │   │   │  (Абсолют: планеты, дома, арканы, формулы)
│   │   └─────────────────────────┘   │   │
│   └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

# Архитектура

| Название зоны  | Предназначение       | Пример       |
|----------------|----------------------|--------------|
| Application    | Интерфейс доступа    | GeoService   |
| Domain         | Изолированная логика | CityTypes    |
| Infrastructure | Внешние зависимости  | Eloquent     |
| Presentation   | Слой отображения     | Translations |

## Подробно

Application связывает между собой Domain и Infrastructure, являясь центральной точкой входа в домен.

Domain хранит независимую логику, которую можно скопировать в любой PHP проект, и она заведётся.

Infrastructure хранит все Laravel-зависимости `use Illuminate\`, и связь с 3rd-party `Http -> google.api`.

Presentation в нашем проекте не нужен, у нас есть глобальный слой UI рядом с модулями.

## Domain

Домен несёт в себе онтологический принцип: идея навязывает структуру папок, - не наоборот.

```
   Types  --→    Atoms  --→  Molecules  --→  Organisms --→  Containers
   (типы)    (примитивы)      (связки)       (системы)      (коллекции)
```

Мы специально оживили семантику вместо академичности, чтобы животь ощущалась в каждом пикселе на экране.

### Схематично

Иерархия идёт сверху-вниз, от Vocabulary к Containers.

| Имя          | Предназначение              | Пример          |
|--------------|-----------------------------|-----------------|
| `Types`      | Имя примитива константой    | AspectTypes     |
| `Atom`       | Атомарный примитив.         | Aspect          |
| `Molecule`   | Композиция атомов.          | Birthday        |
| `Organisms`  | Агрегация в единую систему. | Natal           |
| `Containers` | Коллекции любых энтити.     | AspectContainer |

Любая логика выносится в отдельные, семантические слои, символически привязанные к домену.

### О домене

Сам по себе, домен - это система связей и графов, которая красиво отображает данные в объектах PHP.

По сути, если убрать доменную область, мы теряем красивую семантику, образ мышления, и получаем `raw array of data`.

Домен нужен, чтобы вместо `$natal['planets']['sun']['sign']['name']` иметь `$natal->sun()->sign()->name()`.

А вместе с тем, получить красивую архитектуру папок и файлов внутри домена.

Так же, вторичное, но не первоначальное его предназначение - хранение логики в семантических слоях, если нужно.

Первично он выступает обёрткой (Wrapper) над данными (Data). Вторично - хранилище PHP-логики в предметной области.
